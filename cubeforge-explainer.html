The Big Picture

What Exactly Is Cubeforge?

Think of it as a toolkit that lets developers build video games inside a web browser — but using the same tools they already use to build websites.

🧱

Like LEGO for Games

You snap together pre-built pieces: a player piece, a physics piece, a camera piece. Each piece does one job. Together they make a game.

🌍

Runs in a Browser

No downloads, no install, no app store. Your game lives on a webpage. Anyone with a browser can play — on any computer or phone.

⚛️

Built on React

React is the most popular tool for building websites. Cubeforge extends it so you can describe a game the same way you'd describe a webpage.

📦

A Complete Package

Physics, sound, camera, multiplayer, animation, collision — all included. You don't have to build any of that from scratch.

🎯

For Web Developers

If you already know how to build websites with React, you can start making games immediately. No new language, no new tool to learn.

🔓

Free & Open Source

Anyone can use it, modify it, and contribute to it. The code is publicly available on GitHub under the MIT license.

How It Works

From Code to Playable Game

Here's how a Cubeforge game comes to life, step by step — explained without jargon.

1

You Describe Your World in JSX

Instead of writing instructions like "move the player left," you describe what exists: "there is a player, there is a platform, there is an enemy." This is called declarative programming — like writing a set design instead of a stage direction.

// This is all you need for a basic platformer world: <Game width={800} height={500} gravity={980}> <World background="#1a1a2e"> <Camera2D followEntity="player" /> <Player x={100} y={300} /> <Enemy x={500} y={300} /> <MovingPlatform x1={200} y1={350} x2={450} /> </World> </Game>
2

Entities Are Built from Components

Every object in the game (player, enemy, coin) is an Entity. An entity has no behavior on its own — you give it Components which are little data packages. "This entity has a position." "This entity has gravity." "This entity has a collision box." The combination of components defines what the entity is and does.

// A player entity = several components stacked together <Entity id="player"> <Transform x={100} y={300} /> ← Position in the world <Sprite width={32} height={48} /> ← Visual appearance <RigidBody /> ← Affected by gravity <BoxCollider width={32} height={48} /> ← Has a solid hitbox <Script update={movePlayer} /> ← Custom movement logic </Entity>
3

Systems Run Every Frame

60 times per second, Cubeforge's engine runs Systems — little programs that scan all entities and do things to them. The Physics System moves entities with gravity. The Render System draws them to the screen. The Input System checks your keyboard. They all work together like an orchestra.

// Every 1/60th of a second, Cubeforge runs: PhysicsSystem → applies gravity, detects collisions, moves bodies InputSystem → reads keyboard/mouse/gamepad ScriptSystem → runs your custom update() functions RendererSystem → draws everything to the canvas using WebGL2 AudioSystem → plays sounds at the right moment
4

React Syncs the Game Tree

When your React component adds or removes an entity (e.g. "a coin was collected, remove it"), React tells the game engine. You don't manage any of that manually. It's like toggling a light switch — the wiring is hidden.

// Coins appear and disappear automatically: {coins.map(coin => ( <Entity key={coin.id}> <Transform x={coin.x} y={coin.y} /> <Sprite color="#fbbf24" /> </Entity> ))} // When a coin is collected → removed from the list → vanishes from game

The Packages

8 Modules That Form the Engine

Cubeforge is split into separate modules. You only include what you need — keeping your game's file size small.

cubeforge
Main Package
The only import most developers need. Re-exports everything: Game, World, Entity, Sprite, RigidBody, BoxCollider, and all hooks.
React Components
@cubeforge/core
Engine Brain
The ECS (Entity Component System), game loop, event bus, asset manager, tweening, pathfinding, steering, and deterministic RNG. The heart of everything.
ECS · Loop · Events
@cubeforge/physics
Physics Engine
Gravity, AABB collision, rigid bodies, kinematic mode, one-way platforms, slopes, joints, and a spatial broadphase for performance. Runs at a fixed 60 Hz.
Gravity · Collision · Joints
@cubeforge/renderer
Visual Layer
Cameras, sprites, spritesheet animations, particles, trail effects, parallax backgrounds, nine-slice panels, gradient fills, text rendering, and post-processing.
Draw · Animate · Camera
@cubeforge/input
Controls
Keyboard, mouse, gamepad, and touch support. Input mapping (rebindable keys), combo detection, per-player contexts, and recording/playback for replays.
Keyboard · Mouse · Gamepad
@cubeforge/audio
Sound System
Web Audio API wrapper. Spatial 3D sound, volume groups (music vs SFX), fade in/out, audio ducking when paused, and smooth crossfade between tracks.
SFX · Music · Spatial Audio
@cubeforge/webgl-renderer
GPU Rendering
WebGL2 instanced renderer. Draws thousands of sprites in a single GPU draw call using shaders — far faster than drawing sprites one by one.
WebGL2 · GPU · Instancing
@cubeforge/net
Multiplayer
Room abstraction over WebSockets, syncEntity to replicate state across players, client-side prediction with rollback for lag compensation. Build real-time multiplayer games.
WebSockets · Rollback · Sync
